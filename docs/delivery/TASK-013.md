# TASK-013: Unified design input and interactive 2D preview

Status: implemented and locally verified; not externally approved or released

- Approved baseline: product v0.2, authorized foundation v0.1 overlay (D-012), human reference D-013, suit seed D-014.
- Implementation authorization/source: user interface-refinement request of 2026-09-27, recorded as D-015.
- Requirement IDs and canonical files: UX-003, UX-004, UX-005 in `docs/ux/SCREENS.md` and `docs/ux/FOUNDATIONS.md`; UX-013 and UX-015 in `docs/ux/INTERACTIONS.md`; VIS-001, VIS-002, VIS-005 and VIS-006 in `docs/visualization/ASSET-CONTRACT.md`.
- Acceptance scenario IDs: local portions of AC-02, AC-06, AC-07 and AC-08.
- User-visible outcome: all design input sits in the left pane. A tab switch chooses **Ask your tailor** (conversation and guided quick choices) or **Choose details** (a hierarchy: All details → The essentials / Jacket / Trousers / Vest / Accents → group → options, with breadcrumb, back and previous/next stepping). Both paths call the same design command. The right pane shows a **2D/3D** switch; the selection never changes when switching. Under the preview, every current choice is an editable tag, shown one branch at a time with counts, so 20+ choices do not clutter the view. A tag opens its editor on the left. The 2D technical drawing zooms to the area of the group being edited or the choice just changed — from a field, a guided chip or an accepted assistant suggestion — shows a callout with the current value, switches to back or inside views where the detail lives, and fades the jacket to reveal trouser or vest details. It supports drag to pan, wheel/double-click and button zoom, keyboard arrows and +/−, reset, front/back/inside views, and edit markers that open the matching editor.
- In-scope surfaces/modules: `src/modules/configuration/design-outline.ts` (single hierarchy for navigator, tags and focus; change detection), `src/visualization/focus-regions.ts`, `src/visualization/sketch-spec.ts`, `src/visualization/garment-sketch.tsx`, `src/components/design-navigator.tsx`, `src/components/selection-tags.tsx`, `src/components/design-consultation.tsx`, `src/components/studio.tsx`, styles, unit and browser tests.
- Dependencies and blocking questions: none new. Q-011, Q-014 and Q-023 still gate commercial catalog and asset use.
- Explicit non-goals: changes to 3D behaviour (the user asked that 3D remain as is), pattern drafting, cloth or fit simulation, collecting monogram text, new dependencies, schema changes.
- Data/API/asset contracts: no API or database change. Tags, navigator and drawing read `Draft.design`; edits use the existing `design` command. Suit lapel, pocket and fastening appear once, in the jacket catalog, because the engine already maps them to the legacy fields. Accessory, lining, thread, button and patch fills use the supplied option thumbnails; no colour, stock or price is invented. Trouser fabric for blazers is the same neutral reference as the 3D view.
- Loading/error/empty/recovery behavior: the 2D drawing is plain SVG and needs no model download; 3D keeps its existing loading and fallback states. Group sections that only apply after an accent is added (for example a tie product) appear only when relevant. Unselected catalog values show “Not chosen”.
- Authorization and privacy requirements: unchanged. No personal data added; monogram shows labelled sample initials only.
- Migration/compatibility implications: none. Existing drafts render unchanged. The Fabric/Fit/Details/Style/Accents bottom tabs were replaced by the navigator.
- Test fixtures (synthetic or authorized): synthetic guest drafts only.
- Verification plan: typecheck, lint, unit tests, production build, full Playwright suite including a new 2D synchronisation scenario, visual inspection at 1440×900, 768×1024, 390×844 and 320×740.
- Actual verification evidence: typecheck, lint, 24 unit tests, production build and all 9 Playwright scenarios passed after one test-navigation correction; axe reported no violations on either input mode. Details in [TEST-EVIDENCE](../implementation/TEST-EVIDENCE.md).
- Deviations and decision references: D-015. Default preview on the design step is 2D; measurement and review steps keep the 3D reference because measurement paths exist only there.
- Remaining limitations: the drawing is an illustrative technical sketch, not a validated construction drawing; mapped shapes have not been reviewed by a tailor. Hover preview before selection (S-03) is not implemented. 3D visual quality is unchanged (see STATUS for options). No real-device or screen-reader certification.
