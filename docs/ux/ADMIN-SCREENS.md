# Admin panel and commerce screens

Status: proposed v0.3 under D-019 (2026-09-28). Requirements ADM-003 to ADM-006. This file expands S-10 (Admin catalog) and S-11 (Tailor review) from [SCREENS.md](SCREENS.md) into ADM-01 to ADM-19, and specifies the customer changes to S-01, S-02, S-03, S-08, S-09, S-12 and S-13. The shared screen contract in SCREENS.md (idle, loading, success, empty, error, unauthorised and unavailable states; one primary action; explained disabled actions) applies to every screen here. Endpoints are in [API-REFERENCE.md](../architecture/API-REFERENCE.md).

No new UI library: reuse `src/components/ui/*`, Radix Dialog/Tabs, lucide icons, Tailwind and the existing fonts (OPS-001). Tables are semantic HTML tables. There is no drag-only interaction.

## 1. Principles for an intuitive admin (ADM-004)

1. **One mental model, shown everywhere**: Product → Part → Option group → Option → Choice (glossary in [CATALOG-ADMIN.md §1](../domain/CATALOG-ADMIN.md#1-glossary)). The structure editor is a tree that mirrors the customer navigator: the admin sees the same tabs (Essentials, Jacket, Trousers, Vest, Accents) the customer will see.
2. **Edit in place, save per panel**: selecting a tree node opens its detail panel on the right. Each panel has its own Save and Discard, with a dirty-state guard when navigating away. A save conflict (409 `stale_row_version`) shows “Someone else changed this — review their version” with a side-by-side of the changed fields, and actions **Keep theirs** and **Apply mine again**.
3. **Always show what the customer will pay**: every price field shows the effective customer amount (product override applied) and a one-line explanation (“Charged once when the customer changes anything in *Lining* from the default”). PRC-003 wording lives in `src/modules/pricing/explain.ts` so the UI and docs agree.
4. **Show problems where they are**: validation badges (red = publish error, amber = warning) appear on tree nodes and list rows and bubble up to parents. Clicking a badge jumps to the field.
5. **Nothing reaches customers by accident**: a persistent publish bar shows “Live: v7 · 12 unpublished changes · 0 errors · 3 warnings · **Review & publish**”. Only live fabric availability bypasses publishing, and its control is labelled **Live — updates the store immediately**.
6. **Preview before publishing**: **Preview as customer** opens the studio with the working catalog (staff preview draft), deep-linked to the selected product and group.
7. **Fast bulk work**: multi-select with checkboxes on choice lists and fabric grids. Bulk actions: set surcharge, set status, set band, set availability. Duplicate a group, choice, fabric or template.
8. **Keyboard complete**: every action is reachable by keyboard. Reordering uses **Move up / Move down** buttons and **Move to position…**. Focus returns to the moved row. Tree navigation uses arrow keys (WAI-ARIA tree pattern).
9. **Plain language, with codes secondary**: codes appear as small monospace text under names, are editable until first publish, and are then locked with a tooltip explaining why (CAT-015).
10. **Safe destructive actions**: Archive is the default. Delete appears only for never-published items and asks for confirmation naming the item.

Viewports: catalog editors are verified at 1440 and 1024, and must remain operable at 768. Order desk, order detail, review decision and status updates must also work at 390, because operations staff update tracking from a phone. Customer screens keep the existing 1440/768/390/320 checks.

## 2. Information architecture

```
/admin                       ADM-01 Dashboard
/admin/catalog/products      ADM-02 Products & options (tree editor)           catalog.read / catalog.write
/admin/catalog/fabrics       ADM-04 Fabrics list  →  /admin/catalog/fabrics/[id]  ADM-05 Fabric editor
/admin/catalog/lists         ADM-06 Lists (lookups)
/admin/catalog/pricing       ADM-07 Pricing
/admin/catalog/templates     ADM-08 Looks (templates) → /[id] ADM-09 Look editor
/admin/catalog/rules         ADM-03 Rules
/admin/catalog/media         ADM-19 Media library
/admin/catalog/publish       ADM-10 Publish & history
/admin/orders                ADM-11 Order desk     →  /admin/orders/[id]  ADM-12 Order detail
/admin/reviews               ADM-13 Tailor review queue  →  /admin/reviews/[id] ADM-14 Tailor review decision
/admin/suppliers             ADM-15 Suppliers      →  /admin/suppliers/[id] ADM-16 Supplier detail
/admin/customers             ADM-18 Customer lookup (support)
/admin/settings              ADM-17 Settings: Commerce · Staff & roles · Audit log
/admin/security              MFA enrolment (reachable without MFA)
```

Sidebar items are shown only when the user has the permission for them (hiding is a convenience; the server still enforces). The header shows the signed-in staff name, roles and **Preview as customer**.

## 5. Copy rules

- Never show `$0.00` for an unknown price. Use “Price not yet available”.
- Surcharges read “+$X”. Included choices read “Included”, not “$0”.
- Status labels follow FUL-004 and REVIEW-PAYMENTS.md, and never claim production before release.
- Measurement ownership (D-020): customer copy says the garments are made to the measurements the customer confirmed. It never implies that Vessy or the AI verified their fit. “Tailor verified” appears only after a tailor ticks it in a tailor review.
- Reference-only data shows the admin banner “Reference data — not orderable in production”. Customers see today’s reference notice while the release is reference-only.
- Dates use the operations timezone for supplier deadlines and the customer’s locale for their own timeline.
